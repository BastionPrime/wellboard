# Phase 7 Decisions (OPE-2271)

Фаза 7 — закалка и релиз v1 (initial TZ раздел 7). Нумерация
продолжает DECISIONS.md (D1-D22) и DECISIONS-phase6.md (D23-D28).

## Decisions

- **D29 — LAN-only слушание через --bind, дефолт br-lan (NFR-2.1).**
  До Фазы 7 `cmd/wellboard/main.go` слушал `:8090` (все интерфейсы;
  защита была только firewall-дефолтом OpenWrt). Вместо честной записи
  «отложено» сделан мини-фикс (дешёвый: один флаг + резолвер): флаг
  `--bind` принимает IP, имя интерфейса или пустую строку
  (все интерфейсы, явный opt-in). Прод-дефолт без флага — первый IPv4
  интерфейса `br-lan`; если br-lan не разрешается — предупреждение в
  лог и loopback (старт-фейл оставил бы семью без UI, а loopback не
  WAN). Dev-режим — 127.0.0.1. UCI: `wellboard.main.bind` (unset →
  дефолт; пусто → все интерфейсы), init-скрипт передаёт флаг. Выбор
  дефолта в runtime, а не хардкод IP: у заказчика и в песочнице
  подсети разные; имя br-lan стабильно на OpenWrt. Риск: BPI-R4 с
  нестандартной конфигурацией мостов — покрывается `--bind`/UCI.
  Проверено юнит-тестами (cmd/wellboard/main_test.go) и тем, что
  e2e/stable-тесты зелёные.

- **D30 — Найден и закрыт дефект: инъекция в rules-строки YAML.**
  Аудит пробным тестом показал: yaml.v3 корректно квотирует имена
  прокси/групп (`evil: name` → `'evil: name'`), но rules — плоские
  строки `TYPE,value,group`; значение условия с запятой
  (`domain: "a,b"`) рендерилось как `DOMAIN,a,b,rt:rt_1` — лишний
  сегмент правила (изменение маршрутизации). Ни API, ни генератор это
  не проверяли. Закрыто в обеих точках: 400 на входе
  (validateRouteIn, internal/api/api.go) и отказ генерации
  (conditionRule, internal/generator/generator.go) — вторая страховка
  для state из import или отредактированного руками state.json.
  Запрещены ',', ':' и переводы строк. Провал фиксируется тестами.

- **D31 — Auth/CSRF: статус и план (NFR-2.2/2.4).** В dev-контуре
  аутентификации нет (задокументировано в AUDIT-phase7.md п. 6):
  мутации доступны без auth, CSRF-токена нет. Частичная митигация уже
  в коде: dev слушает 127.0.0.1, прод-дефолт br-lan (D29), все мутации
  — JSON + strict decode (форма с чужого сайта с text/plain будет
  отклонена как invalid JSON; simple-запросы с другим content-type не
  проходят decodeStrict). Точка подключения существует:
  `api.MonitorConfig.Auth` (monitoring.go, сейчас nil в dev, гейтит
  /ui/metacubexd и /api/mihomo). План на прод (по ТЗ Q5): ubus
  `session login` паролем root, cookie HttpOnly; SameSite=Strict;
  масштабирование хука на весь mux. Не сделано в v1, потому что
  требует решения по сессиям на роутере и не блокирует 家庭-сценарий на
  LAN (см. риск RK11). Без auth не выставлять bind=''/WAN — это
  documented в wellboard.config.

- **D32 — Export/import (FR-6.5).** `GET /api/v1/export` — конверт
  {format:1, app, version, state} + Content-Disposition
  (wellboard-state.json). HWID не входит в state.json никогда (живёт в
  отдельном файле hwid, internal/hwid), поэтому «не экспортируется по
  умолчанию» выполняется автоматически; тест генерирует реальный HWID
  в каталоге state и проверяет отсутствие его и соли в экспорте.
  Галочки «экспортировать HWID» (опция из ТЗ) не добавлена: соль —
  секрет, экспорт с солью ломает смысл HWID; перенесено в BACKLOG.
  `POST /api/v1/import`: strict decode 1 MiB, проверка формата конверта
  (99 → 400), версии схемы (newer → 400, даунгрейд — допустим, миграция
  в store), референциальная целостность через generator ДО записи
  (битый импорт → 409, прежнее состояние нетронуто). Замена состояния
  полная (не merge) — это сценарий «перенос на другой роутер» из ТЗ.

- **D33 — Лог-файл 0644, секретов в нём нет.**
  `internal/applog/applog.go` пишет wellboard.log с 0644 (O_APPEND).
  В лог не попадают URL подписок (guardrail 5, updater.go) и API-секрет
  (только Bearer в исходящий запрос). Локально читабельно всеми
  пользователями роутера — на OpenWrt это практически только root;
  риск принят, харденинг (0600) — одна строка при prod-эскалации, но
  меняет права файла при обновлении у уже развернутых инсталляций,
  отложено сознательно.

- **D34 — v1.0.0-candidate, тег не ставится.** Функциональность и
  чек-лист безопасности Фазы 7 закрыты (см. docs/AUDIT-phase7.md),
  релиз v1.0.0 кандидат готов. Тег НЕ проставлен: публичный релиз
  заблокирован лицензионным вопросом — импорт
  `github.com/metacubex/mihomo v1.19.31` (GPL-3.0, см. DECISIONS RK5,
  C6) несовместим с MIT-планом заказчика (Q8) без решения; эскалация у
  adm. README и LICENSE это отражают (MIT + пометка «GPL question
  open»). Тег v1.0.0 будет поставлен после решения владельца.

## Deferred / Open (не в v1)

- Auth по ubus session login + CSRF-токен — прод-фаза (D31).
- Экспорт HWID с явной галочкой и предупреждением — BACKLOG (D32).
- Лог-файл 0600 в проде — тривиально, при прод-эскалации (D33).
- Реальная проверка сценария «семья» на BPI-R4 заказчика — чек-лист
  docs/MANUAL_TEST.md, статус pending у владельца (в песочнице не
  проверяемо, как и sysupgrade из Фазы 6).
- opkg/apk-установка пакета на реальном роутере (RK8) — вместе с
  сценарием владельца.
