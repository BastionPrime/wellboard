# WellBoard — HTTP API

Справочник по HTTP-API WellBoard (версия 1, префикс `/api/v1`).
Описание пользовательского интерфейса — в `README.md`, установка — в
`INSTALL.md`, совместимость — в `COMPATIBILITY.md`.

Актуально для ветки, где появились вход по паролю root (ubus) и
раздельные источники geosite/geoip. Порт по умолчанию — **8090**,
слушает только LAN-адрес (`br-lan`), см. `/etc/config/wellboard`.

## Общие правила

- Тело запроса и ответа — JSON. Неизвестные поля в теле запроса
  **отклоняются** (строгий разбор), поэтому опечатка в имени поля даёт
  `400`, а не молчаливое игнорирование.
- Идентификаторы объектов выдаёт сервер (`sub_`, `srv_`, `grp_`,
  `rt_`) — клиент их не выбирает.
- Секреты (URL подписок, пароли, HWID) не возвращаются списками: в
  `/settings` URL источника приходит замаскированным (`masked_url`).
- Ошибка — объект `{"error": "<текст>"}`; конфликты ссылок (маршрут
  потерял цель, коллизия имён) — `409`, невалидные данные — `400`.
- Метод проверяется маршрутом: неподходящий метод даёт `405`.

## Аутентификация и CSRF

WellBoard не заводит свою базу паролей: вход выполняется **паролем root
роутера**, который проверяется через ubus `session login` — тот же
бэкенд, что у LuCI. Полученный ubus-идентификатор сессии используется
только как доказательство пароля и не сохраняется.

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/auth/login` | `{"password": "..."}` → ставит cookie, возвращает CSRF-токен |
| `GET` | `/auth/session` | Текущее состояние входа (без побочных эффектов) |
| `POST` | `/auth/logout` | Завершает сессию, чистит cookie |

Ответ всех трёх:

```json
{
  "required": true,
  "authenticated": true,
  "username": "root",
  "csrf": "<токен>",
  "expires_in_sec": 43200
}
```

- `required: false` — на этой сборке вход отключён (dev-режим или
  `option auth '0'` в `/etc/config/wellboard`); интерфейс сразу
  открывает панель.
- `authenticated: false` при `required: true` — нужен вход.

Механика:

- Cookie `wb_session` — HttpOnly, `SameSite=Lax`, TTL 12 часов.
  Рестарт службы завершает все сессии (пароль запрашивается заново).
- Cookie `wb_csrf` — HttpOnly; клиент получает значение из
  `/auth/session` или из ответа `/auth/login`.
- **CSRF:** любой запрос, меняющий состояние (`POST`/`PUT`/`PATCH`/
  `DELETE`), обязан повторить токен в заголовке `X-CSRF-Token`.
  Несовпадение → `403`. Заголовок `Origin`, если он есть, должен
  совпадать с `Host` (межсайтовый запрос → `403`).
- Подбор пароля ограничен: 5 неудач с одного адреса в течение минуты →
  `429` + `Retry-After: 60`.
- Транспорт до ubus: сначала HTTP-bridge `http://127.0.0.1/ubus`
  (пароль не попадает в список аргументов процесса); если bridge
  недоступен — CLI `ubus call session login` (в этом случае аргументы
  процесса видит root; переопределяется флагом `--ubus-url` /
  `WELLBOARD_UBUS_URL`).
- `503` на `/auth/login` означает, что ubus недоступен (служба
  `ubus`/`rpcd` не отвечает) — это не «неверный пароль».

Все маршруты `/api/...`, кроме `GET /api/v1/health` и самих
`/api/v1/auth/*`, требуют сессии. Статика интерфейса (SPA,
`/ui/metacubexd/`) отдаётся без входа — данные за ней защищены.

## Состояние и настройки

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/state` | Полное состояние (настройки + источники/серверы/группы/маршруты/LAN) |
| `GET` | `/settings` | Настройки + `sources_summary` (маскированные URL) |
| `PATCH` | `/settings` | Частичное обновление настроек |
| `GET` | `/profile` | Предпросмотр YAML-профиля mihomo |
| `GET` | `/export` | Выгрузка состояния в JSON |
| `POST` | `/import` | Импорт состояния (полностью заменяет текущее) |

`PATCH /settings` принимает поля: `ui_port`, `lang`,
`geosite_source`, `geoip_source`, `geosite_custom_url`,
`geoip_custom_url`, `geodata_additions`, `default_policy`,
`delay_test_interval_sec`.

- `geosite_source` / `geoip_source` — независимые значения:
  `runetfreedom`, `metacubex` или `custom`.
- `custom` требует соответствующего `*_custom_url` (URL источника).
- `geodata_additions` — свои домены/CIDR поверх категории:
  `{"<категория>": ["example.com", "10.0.0.0/8"]}`.

## Источники, серверы, группы, маршруты

| Метод | Путь | Назначение |
|---|---|---|
| `GET`/`POST` | `/sources` | Список / создание подписки или ручного источника |
| `POST` | `/sources/import-nikki` | Поиск подписок в конфиге nikki (read-only) и создание источников |
| `GET`/`PATCH`/`DELETE` | `/sources/{id}` | Чтение / правка / удаление |
| `GET`/`POST` | `/servers` | Пул прокси: список / ручное добавление |
| `GET`/`DELETE` | `/servers/{id}` | Чтение / удаление |
| `GET`/`POST` | `/groups` | Группы прокси (`select`, `url-test`, `fallback`, `load-balance`) |
| `GET`/`PATCH`/`DELETE` | `/groups/{id}` | Чтение / правка / удаление |
| `GET`/`POST` | `/routes` | Правила маршрутизации (порядок применения) |
| `GET`/`PATCH`/`DELETE` | `/routes/{id}` | Чтение / правка / удаление |

- `POST /sources`: `{"kind": "subscription"|"manual", "name",
  "url", "enabled", "update_interval_sec"}`.
- `POST /sources/import-nikki`: `{"name"}` — необязательное имя для
  созданных источников; сам конфиг nikki не изменяется.
- `POST /servers`: `{"links": "<share-ссылки, по одной в строке>"}`.
- `PATCH /routes/{id}`: `name`, `enabled`, `order`, `conditions`
  (`[{"type": "...", "value": "..."}]`), `target`, `on_unavailable`,
  `providers`.

## Шаблоны

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/templates` | Каталог: штатные + пользовательские (`origin: "builtin"\|"custom"`) |
| `POST` | `/templates` | Создать пользовательский шаблон (или переопределить штатный) |
| `GET` | `/templates/{id}` | Один шаблон |
| `PUT` | `/templates/{id}` | Изменить (пишет файл оверлея) |
| `DELETE` | `/templates/{id}` | Удалить оверлей (штатный шаблон возвращается) |
| `POST` | `/templates/{id}/toggle` | `{"disabled": true\|false}` — включить/выключить |
| `POST` | `/templates/{id}/apply` | `{"target": {...}}` — создать маршрут из шаблона |

Пользовательские шаблоны и переопределения живут в **оверлее**
`/etc/wellboard/templates` (каталог состояния, попадает в
`/lib/upgrade/keep.d` и переживает sysupgrade); штатный каталог
`/usr/share/wellboard/templates` при этом не изменяется. Выключенные
шаблоны сохраняются в `settings.disabled_templates` и не предлагаются
к применению (`apply` по выключенному → `409`).

Тело создания/изменения:

```json
{
  "id": "my-rules",
  "name": "Мои правила",
  "description": "...",
  "list_source": "...",
  "conditions": [{"type": "geosite", "value": "category-ads-all"}],
  "typical_target": "reject",
  "providers": ["geosite"]
}
```

`id` должен соответствовать `[a-z0-9-]{1,64}`.

## Геоданные

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/geodata/tags?kind=geosite\|geoip` | Известные категории для редактора шаблонов |

Разделение источников и добавление своих адресов — через
`PATCH /settings` (см. выше). Добавления участвуют и в генерации
профиля, и в проверке доступности категорий.

## Внешние правила nikki

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/external-rules` | Правила активного конфига mihomo (только чтение) |
| `POST` | `/external-rules/import` | `{"rule", "name", "target"}` — скопировать одно правило как маршрут |

WellBoard не изменяет `/etc/nikki`: вкладка читает
`/etc/nikki/run/config.yaml` и ничего туда не пишет. Импортированный
маршрут создаётся выключенным.

## Применение профиля, логи, диагностика

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/apply` | Сгенерировать профиль, применить, проверить здоровье, откатить при сбое |
| `GET` | `/applied` | Что применено сейчас (профиль, время, результат) |
| `POST` | `/rollback` | Откат к предыдущему рабочему профилю |
| `GET` | `/pending` | Есть ли неприменённые изменения |
| `GET` | `/logs` | Хвост логов приложения и nikki/mihomo |
| `GET` | `/diagnostics` | Проверки nikki, mihomo API, геоданных |

## LAN-устройства

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/lan-devices` | Список устройств (DHCP-лизы + ubus-фолбэк) |
| `POST` | `/lan-devices/static` | `{"mac", "ip", "hostname"}` — закрепить статический лиз |

Ответ `{"status": "simulated", "detail": "..."}` означает, что лиз не
закреплён (на этом хосте нет управления DHCP) — предупреждение, а не
ошибка.

## Служебные маршруты

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/v1/health` | Проверка живости; **публичный**, без входа |
| `GET` | `/ui/metacubexd/` | Панель мониторинга metacubexd (если собрана) |
| `*` | `/api/mihomo/*` | Прокси к API mihomo (нужна сессия) |
| `GET` | `/` | SPA (Vue 3), hash-роутинг |

## Коды ответов

| Код | Когда |
|---|---|
| `200` / `204` | Успех (204 — logout, удаление) |
| `400` | Невалидное тело/значение поля |
| `401` | Нет сессии или неверный пароль |
| `403` | Нет CSRF-заголовка / несовпадение токена / межсайтовый Origin |
| `405` | Метод не поддерживается этим маршрутом |
| `409` | Конфликт ссылок: цель маршрута потеряна, коллизия имён, выключенный шаблон |
| `429` | Слишком много неудачных попыток входа (см. `Retry-After`) |
| `503` | Каталог шаблонов или ubus недоступны |

## Пример сессии

```sh
BASE=http://192.168.1.1:8090/api/v1

# 1. Вход (пароль root роутера).
#    -c сохраняет cookie в файл, ответ содержит csrf.
curl -s -c /tmp/wb.jar -H 'Content-Type: application/json' \
  -d '{"password": "<пароль root>"}' "$BASE/auth/login"

# 2. Чтение состояния — достаточно cookie.
curl -s -b /tmp/wb.jar "$BASE/state"

# 3. Изменение — нужен заголовок X-CSRF-Token со значением из шага 1.
curl -s -b /tmp/wb.jar -H 'X-CSRF-Token: <csrf>' \
  -H 'Content-Type: application/json' \
  -d '{"geosite_source": "custom", "geosite_custom_url": "https://example/geosite.dat"}' \
  -X PATCH "$BASE/settings"

# 4. Выход.
curl -s -b /tmp/wb.jar -H 'X-CSRF-Token: <csrf>' -X POST "$BASE/auth/logout"
```

Проверка живости без входа:

```sh
curl -s "$BASE/health"
```
