# WellBoard 1.0.4 — что нового и как ставить

Релиз 1.0.4 делает WellBoard рабочим на роутере владельца, не ломая уже
настроенный nikki: свой профиль пишется рядом с существующими, выбор
профиля идёт одной опцией UCI, при неудаче конфигурация возвращается к
той, что была до WellBoard.

## Главное

1. **Настоящий nikki-адаптер на роутере.** В боевом режиме WellBoard
   больше не «симулирует» применение:
   - пишет сгенерированный профиль в `/etc/nikki/profiles/`;
   - выбирает его `uci set nikki.config.profile=<имя>` + `uci commit nikki`;
   - перезапускает nikki (`/etc/init.d/nikki restart`);
   - проверяет живость через mihomo external-controller (`/version`);
   - если за 15 с ядро не поднялось — автоматически возвращает профиль,
     который был выбран ДО применения.
   Миксин (`nikki.mixin`) и `run/config.yaml` WellBoard не трогает.
2. **Импорт текущих правил без изменений в рабочем конфиге.** Вкладка
   «Маршруты» → «Внешние правила nikki» → кнопка «Импортировать все
   правила»: каждое правило активного конфига становится маршрутом
   WellBoard **выключенным**. Рабочий конфиг читается только на чтение,
   его sha256 до и после импорта совпадает; ничего не применяется, пока
   владелец сам не включит нужные маршруты и не нажмёт «Применить».
   Повторный импорт ничего не дублирует.
3. **Мастер первого запуска — только по кнопке.** Автоматический
   редирект на мастер убран; мастер открывается кнопкой «Запустить
   мастер настройки» в Настройках.
4. **LuCI.** `redirect.js` в `luci-app-wellboard` теперь настоящий
   LuCI-view (`view.extend` вместо `baseclass.extend`) — ошибка в LuCI
   уходит.
5. **Пользовательские шаблоны и геоданные.** Свои шаблоны
   (`/etc/wellboard/templates`, переживают sysupgrade), раздельные
   источники geosite/geoip, свои URL и дополнения к спискам.
6. **Пакеты собираются настоящими инструментами.** `.apk` — apk-tools 3
   (`apk mkpkg`, формат v3), `.ipk` — `ipkg-build` из OpenWrt. Ручных
   tar-ов больше нет.

## Установка

### OpenWrt 25.12 (apk)

```sh
apk update
apk add --allow-untrusted /tmp/wellboard-1.0.4-r1-<arch>.apk
apk add --allow-untrusted /tmp/luci-app-wellboard-1.0.4-r1-all.apk
/etc/init.d/wellboard status
```

Пакеты не подписаны, поэтому нужен `--allow-untrusted`.

### OpenWrt 23.05 / 24.10 (opkg)

```sh
opkg update
opkg install /tmp/wellboard_1.0.4_<arch>.ipk
opkg install /tmp/luci-app-wellboard_1.0.4_all.ipk
/etc/init.d/wellboard status
```

Архитектуры: `aarch64_cortex-a53`, `aarch64_generic`, `x86_64`,
`arm_cortex-a7_neon-vfpv4`, `mipsel_24kc`; `luci-app-wellboard` — `all`.

## Что проверить после установки

- `ubus call system board | jsonfilter -e '@.release.version'` — версия
  OpenWrt (25.12 → apk, 23.05/24.10 → opkg).
- `/etc/config/nikki` до и после первого «Применить» — меняется только
  строка `option profile`.
- `sha256sum /etc/nikki/run/config.yaml` до и после импорта правил —
  значение не меняется.
- Если применение не удалось, в UI виден старый профиль: WellBoard
  вернулся к нему автоматически (в истории применения это отмечено как
  `rolled_back`).

## Ограничения этого релиза

- Пакеты не подписаны (`--allow-untrusted`), собственного репозитория
  нет — файлы ставятся вручную.
- Приёмка на живом роутере с копией рабочего состояния nikki (около 59
  правил) остаётся за QA: пакеты проверены на структуру (apk: `apk
  adbdump`; ipk: состав `control.tar.gz`/`data.tar.gz`), но ещё не
  ставились на роутер в этом релизе.
- Правила, которые нельзя выразить маршрутом WellBoard (`PROCESS-NAME`,
  логические правила, `MATCH`), при импорте пропускаются — они видны в
  таблице как «только просмотр».
