# WellBoard — Ручной тест-чеклист для владельца (BPI-R4)

Сценарий приёмки v1 из ТЗ: **«заказчик проходит сценарий "семья":
добавить подписку → применить шаблон "Стриминги через NL" → телевизор
через сервер → всё работает без чтения документации».**

Этот чек-лист выполняется на реальном роутере владельца (BPI-R4) после
установки пакета (см. `docs/INSTALL.md`). В песочнице разработки он не
воспроизводим — статус: **pending, ждёт владельца**.
Отметьте `[ ]` → `[x]` и верните отчёт разработчику.

Подготовка (однократно, делает разработчик или по INSTALL.md):
- [ ] OpenWrt 23.05/24.10/snapshot на BPI-R4, nikki установлен и
      работает (сервис `nikki` active).
- [ ] WellBoard установлен (`opkg install wellboard…ipk` / `apk add`),
      сервис стартовал: `wget -q -O- http://192.168.1.1:8090/api/v1/health`
      отвечает `{"status":"ok",…}`.
- [ ] Роутер раздаёт Wi-Fi/LAN, телевизор и телефон подключены.

Время: ~30-40 минут. Ничего не должно требовать чтения документации —
если потребовалось, это дефект UX: запишите шаг.

## Часть 0. Первый вход (семья не читает мануалы)

- [ ] Открыть `http://192.168.1.1:8090/` с телефона и с ноутбука.
      Панель открывается, язык — русский, интерфейс понятен «на глаз».
- [ ] Экран работает без интернета (отключить WAN на минуту): панель
      открывается, показывает состояние, ошибки — не блокирующие.
- [ ] Мобильный экран (телефон, 360px): главные экраны удобны,
      кнопки нажимаются.

## Часть 1. Добавить подписку

- [ ] «Источники» → «Добавить подписку»: вставить ссылку
      Remnawave-подписки, имя «Семейная», сохранить.
- [ ] Нажать «Обновить»: появился список серверов (NL, DE, …),
      у подписки виден статус, квота трафика и срок.
- [ ] (Если у подписки лимит устройств) В «Настройки → Устройство»
      виден HWID; в карточке подписки — «Лимит устройств
      включён/не достигнут». Панель НЕ должна занимать лишний слот
      устройства при обычных обновлениях.

## Часть 2. Применить шаблон «Стриминги» (через NL)

- [ ] «Шаблоны» → выбрать шаблон **«Стриминги»** (YouTube, Netflix…).
- [ ] В окне применения выбрать цель: сервер/группу **NL**
      (или создать группу «NL» из серверов NL и выбрать её).
- [ ] Нажать «Применить шаблон». Появился маршрут в «Маршруты».
- [ ] Нажать **«Применить»** (кнопка apply). Дождаться зелёного
      статуса. В «Мониторинге» метакубексд-вкладка открывается и
      показывает активные соединения.
- [ ] На ноутбуке открыть youtube.com / netflix.com — работают.
      В «Мониторинг» → соединения видны строки с цепочкой через NL.

## Часть 3. Телевизор через сервер

- [ ] «Устройства»: в списке LAN-устройств найти телевизор
      (по имени/IP, MAC).
- [ ] Зафиксировать ему статический IP (кнопка «Зафиксировать IP»),
      чтобы маршруты по IP не ломались после перезагрузки роутера.
- [ ] «Маршруты» → добавить маршрут: условие
      **«Устройство» = телевизор**, цель — сервер/группа NL.
      Сохранить, «Применить».
- [ ] На телевизоре открыть приложение YouTube/Netflix — работает
      через выбранный сервер.
- [ ] Проверка на телефоне: трафик телефона идёт НЕ через этот
      маршрут (маршрут только для IP телевизора). Например, телефон
      видит RU-контент напрямую, а телевизор — через NL.

## Часть 4. Надёжность (не должно «уронить» роутер)

- [ ] Сломать намеренно: «Маршруты» → маршрут телевизора → цель
      «несуществующий сервер» (удалить сервер, оставив маршрут).
      «Применить» → WellBoard показывает понятную ошибку
      («маршрут потерял цель»), профиль НЕ применяется, интернет
      живой.
- [ ] «Откатить»: после успешного применения изменить что-то и
      нажать «Откатить к предыдущему» — интернет жив, откатился.
- [ ] Перезагрузить роутер (`reboot`): WellBoard поднялся сам,
      настройки и HWID на месте (в т.ч. после `sysupgrade` —
      проверить при плановом обновлении прошивки).

## Часть 5. Экспорт/импорт (бэкап)

- [ ] «Настройки» → «Экспортировать состояние»: скачался файл
      `wellboard-state.json`. Открыть/поискать в нём: **HWID там
      быть не должно**.
- [ ] (Опционально, при переносе) На втором роутере: «Импорт»
      состояние из файла — настройки/маршруты перенеслись.

## Часть 6. Итог приёмки

- [ ] Сценарий «семья» пройден: подписка → шаблон Стриминги →
      телевизор через NL — без чтения документации.
- [ ] Ни на одном шаге роутер не остался без интернета.
- [ ] Замечания по UX (что было непонятно) перечислить отдельно —
      это вход для доработок.

## Если что-то не работает

Диагностика из панели: «Мониторинг → Диагностика» (проверки nikki /
mihomo API / геоданные), «Мониторинг → Логи» (последние строки).
Служебное: `logread | grep wellboard`,
`/etc/init.d/wellboard status`. Прикладывайте вывод при обращении.
