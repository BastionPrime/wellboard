# WellBoard — Ручной тест-чеклист для владельца (BPI-R4)

Обновлён под v1.0.4 (внешние правила nikki, реальный адаптер, вход по
паролю root). Чек-лист сценария приёмки v1 остаётся в силе:
**«заказчик проходит сценарий "семья": добавить подписку → применить
шаблон "Стриминги через NL" → телевизор через сервер → всё работает
без чтения документации».**

Этот чек-лист выполняется на реальном роутере владельца (BPI-R4) после
установки пакета (см. `docs/INSTALL.md` и `docs/RELEASE-1.0.4.md`).
Отметьте `[ ]` → `[x]` и верните отчёт разработчику.

Подготовка (однократно, делает разработчик или по INSTALL.md):
- [ ] OpenWrt 23.05/24.10/25.12 на BPI-R4, nikki установлен и работает
      (сервис `nikki` active; на 25.12 пакеты ставятся через `apk add`,
      на 23.05/24.10 — `opkg install`).
- [ ] WellBoard установлен, сервис стартовал:
      `wget -q -O- http://192.168.1.1:8090/api/v1/health`
      отвечает `{"status":"ok",…}`.
- [ ] Роутер раздаёт Wi-Fi/LAN, телевизор и телефон подключены.

Время: ~40-50 минут (раздел внешних правил — ~10 минут). Ничего не
должно требовать чтения документации — если потребовалось, это дефект
UX: запишите шаг.

## Часть 0. Первый вход (семья не читает мануалы)

- [ ] Открыть `http://192.168.1.1:8090/` с телефона и с ноутбука.
      Появляется экран входа: ввести **пароль root роутера** (тот же,
      что для LuCI) — второго пароля заводить не нужно. После входа
      открывается панель, язык — русский, интерфейс понятен «на глаз».
- [ ] Экран работает без интернета (отключить WAN на минуту): панель
      открывается, показывает состояние, ошибки — не блокирующие.
- [ ] Мобильный экран (телефон, 360px): главные экраны удобны,
      кнопки нажимаются.
- [ ] (Опционально) «Настройки» → «Запустить мастер настройки»:
      мастер проходит по шагам и завершается; сам он НЕ запускается
      автоматически при первом входе (v1.0.4: только по кнопке).

## Часть 1. Добавить подписку

- [ ] «Источники»: заполнить «Название» и «URL подписки», нажать
      «Добавить»: подписка «Семейная» появилась в списке.
- [ ] Нажать «Обновить» (перечитывает список): появились серверы
      (NL, DE, …). Квоты и срок подписки видны на «Главной» в таблице
      «Квоты подписок» (трафик / использовано / истекает).
      Примечание: обновление самой подписки выполняет планировщик,
      кнопка «Обновить» перечитывает текущий список.
- [ ] (Если у подписки лимит устройств) В «Источники» колонка
      «Устройства»: статус привязки; «лимит устройств достигнут»
      показывается отдельной пометкой. Панель НЕ должна занимать
      лишний слот устройства при обычных обновлениях.

## Часть 2. Применить шаблон «Стриминги» (через NL)

- [ ] «Шаблоны» → карточка **«Стриминги»** (YouTube, Netflix…):
      в селекте «Куда направить трафик» выбрать цель — сервер/группу
      **NL** (или сначала «Группы» → «Создать группу» из серверов NL).
- [ ] Нажать «Применить». Появился маршрут в «Маршруты» (создан
      включённым).
- [ ] Нажать **«Применить»** в панели применения (полоса под
      навигацией; статус «Есть неприменённые изменения» →
      «Изменения применены»). Дождаться зелёного статуса. В
      «Мониторинге» метакубексд-вкладка открывается и показывает
      активные соединения.
- [ ] На ноутбуке открыть youtube.com / netflix.com — работают.
      В «Мониторинг» → соединения видны строки с цепочкой через NL.

## Часть 2а. Внешние правила nikki (новое в v1.0.3/v1.0.4)

Раздел «Внешние правила nikki» на вкладке «Маршруты» — только
просмотр: он читает активный конфиг mihomo
(`/etc/nikki/run/config.yaml`) и никогда его не меняет.

- [ ] «Маршруты» → кнопка «Внешние правила nikki»: раздел открылся,
      показал «Всего правил: N. Источник: …/run/config.yaml»
      и таблицу правил (номер, тип, значение, цель).
- [ ] **Неизменность конфига:** до и после всей части 2а сравнить
      `sha256sum /etc/nikki/run/config.yaml` — значение то же.
- [ ] **Список/просмотр:** правила показываются построчно в порядке
      следования в конфиге; у строк без аргумента (например MATCH)
      поле значения пустое; строки вида «только просмотр» (например
      PROCESS-NAME, MATCH) кнопки импорта не имеют.
- [ ] **Импорт одного правила:** у импортируемой строки (например
      `DOMAIN-SUFFIX,example.com,DIRECT`) нажать «Импортировать»:
      появилось сообщение «OK: правило скопировано как маршрут rt_…
      (выключен, включите и "Применить" по желанию)», в списке
      маршрутов появился новый маршрут **выключенным**, имя вида
      `nikki: DOMAIN-SUFFIX example.com`.
- [ ] **Импорт с чужой целью:** у правила, чья цель — имя группы/сервера,
      которого нет в WellBoard (не DIRECT/REJECT), нажать
      «Импортировать»: понятная ошибка «external policy "…" is not a
      WellBoard server/group yet; create it first or pass an explicit
      target». После создания в WellBoard группы с таким же именем
      повторный импорт проходит.
- [ ] **Импортировать все правила:** кнопка «Импортировать все
      правила»: сообщение «OK: импортировано маршрутов N, пропущено S
      (все созданы выключенными; включите нужные и нажмите
      "Применить")». В «Маршрутах» появились новые выключенные
      маршруты; пропущенные (PROCESS-NAME/MATCH/неизвестная политика)
      в счётчике пропусков, рабочий конфиг не тронут.
- [ ] **Повторный импорт не дублирует:** нажать «Импортировать все
      правила» ещё раз: все уже импортированные правила ушли в
      «пропущено» с причиной «already imported», новых дублей нет.
- [ ] **Включение и применение:** включить один импортированный
      маршрут (переключатель в списке) и нажать «Применить» в панели
      применения: профиль применился, правило заработало в mihomo.
- [ ] **Откат после неудачного импорта:** сделать неудачную правку
      (включить маршрут с целью, которая сломалась — например удалить
      сервер, оставив маршрут на него) и нажать «Применить»: панель
      показывает понятную ошибку (профиль не применяется), интернет
      живой. Нажать «Откатить»: вернулся предыдущий применённый
      профиль («Мониторинг»/«Логи» подтверждают), интернет жив.
      Удалить сломанный маршрут (кнопка «Удалить маршрут» в списке
      маршрутов) и «Применить» снова — успешно.
- [ ] (Контроль) `uci show nikki | grep profile` — WellBoard меняет
      только `option profile`, миксин и `run/config.yaml` не тронуты.

## Часть 3. Телевизор через сервер

- [ ] «Маршруты» → «Добавить» (форма маршрута; кнопка «Создать
      маршрут»): в условии выбрать тип
      «src-device» → кнопка «Устройства» → в списке LAN-устройств
      (заголовок «Устройства LAN (DHCP-лизы)») найти телевизор
      (по имени/IP, MAC).
- [ ] Зафиксировать телевизору статический лиз (кнопка «Закрепить
      статический лиз» рядом с устройством в списке выбора), чтобы
      маршруты по IP не ломались после перезагрузки роутера.
- [ ] Завершить форму: цель — сервер/группа NL, «Сохранить»,
      «Применить» в панели применения.
- [ ] На телевизоре открыть приложение YouTube/Netflix — работает
      через выбранный сервер.
- [ ] Проверка на телефоне: трафик телефона идёт НЕ через этот
      маршрут (маршрут только для IP телевизора). Например, телефон
      видит RU-контент напрямую, а телевизор — через NL.

## Часть 4. Надёжность (не должно «уронить» роутер)

- [ ] Сломать намеренно: «Маршруты» → маршрут телевизора →
      «Изменить» → цель «несуществующий сервер» (удалить сервер,
      оставив маршрут). «Применить» → WellBoard показывает понятную
      ошибку (генерация профиля не проходит: «profile generation
      failed (unresolved references)»), профиль НЕ применяется,
      интернет живой.
- [ ] «Откатить»: после успешного применения изменить что-то и
      нажать «Откатить» — интернет жив, откатился к предыдущему
      применённому профилю.
- [ ] Перезагрузить роутер (`reboot`): WellBoard поднялся сам,
      настройки и HWID на месте (в т.ч. после `sysupgrade` —
      проверить при плановом обновлении прошивки).

## Если что-то не работает

Диагностика из панели: «Логи» → «Диагностика» (проверки nikki /
mihomo API / геоданные), «Логи» (последние строки логов приложения
и nikki/mihomo). Служебное: `logread | grep wellboard`,
`/etc/init.d/wellboard status`. Прикладывайте вывод при обращении.
